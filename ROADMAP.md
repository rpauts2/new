# Roadmap: Warframe Companion

Цель: превратить разрозненные скрипты и справочные данные в поддерживаемый инструмент-помощник для Warframe. Этот план охватывает анализ сборок, миссий, данных и удобство использования. Он не включает автономное ведение боя, unattended farming или обход AFK-проверок.

## Текущий прогресс

- [x] Базовый советник по миссиям и ролям варфреймов.
- [x] Ручной журнал миссий с JSONL-хранением, сводкой и CSV-экспортом.
- [x] Поиск наград реликвий по локальному JSON-набору WFCD с фильтрами по эпохе, состоянию и точному названию.
- [x] Unit-тесты для советника, журнала и поиска реликвий.
- [x] GitHub Actions workflow для запуска unit-тестов.
- [x] Документация по установке и использованию.
- [x] Проверить выполнение тестов на GitHub Actions: успешный прогон подтверждён после исправления фильтра состояния.
- [ ] Проверить реальные варианты схемы данных на актуальном файле WFCD.
- [ ] Подключить удобное обновление и отображение даты источника данных.

## Что изучено в сторонних проектах

### YagamiKlait3579/Warframe
- Общие настройки вынесены в `Settings.ahk`, а запуск/остановка управляются общей горячей клавишей.
- Есть отдельные сценарии для конкретных варфреймов, оружия и миссий.
- Общие библиотеки и пользовательские настройки позволяют переиспользовать поведение.
- Есть отдельные файлы для Nekros solo farm и Equinox low-level relic, но не следует переносить их автономные игровые циклы.
- Важные инженерные риски: проект на AutoHotkey v1, зависимость таймингов от FPS и локальных биндов, сценарии могут быть хрупкими при изменении разрешения/настроек.

### Lazy-World/warframe-ahk
- Скрипты разделены на модули и используют общие библиотеки.
- Есть маленький оверлей, индикатор состояния, таймер и предупреждения.
- В README указано, что репозиторий архивирован и не поддерживается.
- `nova_farm.ahk` демонстрирует плотную связанность цикла ввода, настроек, таймеров и GUI. Для нашего проекта это скорее повод разделить логику на независимые компоненты, а не копировать цикл автодействий.
- Перед заимствованием любого кода нужно проверять лицензию, авторство и происхождение файла.

## Принципы архитектуры

1. **Разделение слоёв:** данные Warframe, рекомендации, пользовательский интерфейс, журналирование и тесты не должны зависеть друг от друга.
2. **Один источник правды:** названия способностей, роли, миссии и ротации не дублируются вручную по разным файлам.
3. **Проверяемые данные:** хранить источник, дату получения и версию для каждого набора данных.
4. **Никаких скрытых циклов:** любые разрешённые вспомогательные действия должны быть явно видимыми, иметь понятное состояние и немедленную остановку.
5. **Безопасность запуска:** не хранить токены и секреты в репозитории; проверять конфиги; не запускать загруженные скрипты автоматически.
6. **Лицензии:** фиксировать исходный репозиторий, commit SHA и лицензию для сторонних данных/кода.

## Этапы реализации

### Этап 0. Стабилизация репозитория
- [x] Добавить базовый `.gitignore` для Python-кэша и локальных окружений.
- [x] Зафиксировать поддерживаемую версию Python и инструкции по запуску.
- [x] Добавить unit-тесты и workflow GitHub Actions.
- [x] Проверить, что тесты действительно прошли в CI.
- [ ] Проверить лицензию и происхождение существующих файлов до переиспользования.
- [ ] Удалить из Git ранее отслеживаемые `__pycache__` и `.pyc`, если они ещё присутствуют.

**Готово, когда:** чистый checkout запускается по README, тесты проходят автоматически, временные файлы не попадают в коммиты.

### Этап 1. Надёжная база данных Warframe
- [ ] Проверить актуальные схемы WFCD/warframe-items и WFCD/warframe-drop-data на реальных данных.
- [x] Добавить загрузку набора реликвий с проверкой JSON до замены кэша.\n- [ ] Добавить явную дату/версию данных и проверить совместимость с актуальной схемой.
- [ ] Нормализовать имена варфреймов, способностей, оружия и предметов.
- [ ] Удалить неподтверждённые описания и ошибочные названия из локальной базы.
- [ ] Показывать дату обновления и источник каждой записи.
- [ ] Добавить тесты схемы и проверки на пустые/дублирующиеся записи.

**Готово, когда:** данные воспроизводимо обновляются, ошибки источника не ломают приложение, а устаревшие данные видны пользователю.

### Этап 2. Советник по реликвиям и миссиям
- [x] Базовый поиск награды по локальному JSON с фильтрами и выводом записанной вероятности.\n- [x] Опциональная загрузка набора реликвий одной командой с валидацией кэша.
- [ ] Добавить fixtures с примерами актуальной схемы данных.
- [ ] Сравнение реликвий по ожидаемой ценности наград, только если доступны достоверные вероятности и цены.
- [ ] Фильтры по эпохе, предмету, редкости и доступности.
- [ ] Явно показывать допущения и дату данных.
- [ ] Не выдавать приблизительную оценку за гарантированный доход.

**Готово, когда:** пользователь может выбрать цель и увидеть проверяемый список вариантов с источником данных.

### Этап 3. Советник по сборкам
- [ ] Каталог варфреймов, способностей, оружия и модов из проверенных источников.
- [ ] Рекомендации по роли: выживаемость, поддержка, контроль, добыча ресурсов, урон.
- [ ] Профили для обычных миссий, реликвий, обороны и выживания.
- [ ] Объяснение компромиссов сборки, а не только один «лучший» вариант.
- [ ] Импорт/экспорт сборок в JSON и проверка валидности конфигурации.
- [ ] История изменений и сравнение двух сборок.

**Готово, когда:** рекомендация объясняет, почему выбран варфрейм и какие слабые стороны у сборки.

### Этап 4. Компаньон во время игры
- [ ] Небольшое окно поверх остальных окон с выбранной сборкой, таймером и личными заметками.
- [ ] Горячие клавиши только для управления самим компаньоном.
- [ ] Явные статусы: готов, приостановлен, ошибка источника, данные устарели.
- [x] Ручной журнал миссий: пользователь отмечает результат, награду и реликвию.
- [ ] Не выполнять автономные боевые циклы и не подменять действия игрока.

**Готово, когда:** окно полезно во время миссии, не перехватывает управление игрой неожиданно и не делает игровые решения вместо пользователя.

### Этап 5. Аналитика фарма
- [x] Базовая сводка ручных записей и CSV-экспорт.
- [ ] Скорость получения предмета и количество попыток.
- [ ] Сравнение вариантов фарма с диапазонами неопределённости.
- [ ] Резервное копирование и удаление локальной истории.

**Готово, когда:** пользователь видит фактическую статистику своей игры, а не выдуманные прогнозы.

### Этап 6. Качество и сопровождение
- [x] Unit-тесты для основных функций.\n- [x] Подтвердить успешный GitHub Actions run после исправления state-фильтра.
- [ ] Интеграционные тесты импортёра данных с сохранёнными fixtures.
- [ ] Проверка сетевых ошибок, ограничений API и некорректных данных.
- [x] CI workflow для unit-тестов, ожидает подтверждения фактического запуска.
- [ ] Lint, type checks и проверка зависимостей.
- [ ] Пакетирование под Windows и инструкция по обновлению/откату.
